# 🗺️ Дневник Исследователя (Researcher's Diary)

## 🎯 Концепция и Цели

Приватное PWA для записи маршрутов и сбора «находок» (фото + заметки). Данные хранятся строго локально в браузере (IndexedDB). Пользователь ставит цель перед прогулкой, фиксирует находки в процессе и возвращается к ним в архиве.

## Первичное ТЗ

1. Есть карта, но я не отмечаю на ней ничего - она просто есть, обычная такая карта.
2. Есть человек, который пошёл гулять.
3. Перед прогулкой он формирует цели. Например, "Хочу найти белый цикорий" или "Хочу найти майского жука" или "Хочу найти определенный оттенок цвета" и так далее. Фактически это карточка маршрута. Можно использовать даже "продумывания маршрута на карте", но это неоязательно. Маршрут будет по факту
4. Вот я гуляю, всё хорошо. Пока не вижу своих целей, но вижу что-то другое. Так, что это? Gemma в дикой природе? Нет, это просто редкая гусеница. Я фотографирую ее чем-то вроде Google Объектива, но мне конечно его не дадут, поэтому каким-то аналогом. Зачем? Затем, что эта фотография и краткая информация о том, что это и где я это нашел, отмечается на том самом маршруте, который появляется по ходу моего движения.
5. Закончив прогулку, даже не выполнив цель, у меня должно накопиться определенное количество таких вот интересных заметок. Что с ними делать?
6. Я могу упаковать это в summary. Всё просто, это может быть банально таблица или простой inner landing page. Там видно, где я был, что я нашел и во сколько, а также возможность прочитать информацию о том, что это такое на фото.
7. Конечно прикольно возвращаться к уже пройденным маршрутам и смотреть, что я находил.

### Короткий обзор первичного ТЗ (Core Vision):

1. **Карта**: Визуализация перемещений и отметок.
2. **Целеполагание**: Перед прогулкой создается карточка маршрута с конкретной целью.
3. **Процесс сбора**: Фиксация объектов (фото + описание). Привязка к координатам и времени.
4. **Итог**: Summary (отчет) с путем, находками и временем.
5. **Архив**: История прошлых маршрутов.

## 🛠 Технический стек

- **Frontend**: React, Vite
- **Карты**: Leaflet.js, react-leaflet
- **База данных**: Dexie.js (IndexedCDB)
- **Стили**: CSS (App.css)

### 💾 Структура БД (Dexie)

- `expeditions`: `id, startTime, endTime, title, goal, path`
- `findings`: `id, expeditionId, position, timeStamp, note, image, isGoal`

---

## 🏗 Текущая Архитектура (v0.3)

- `App.jsx`: Контроллер режимов (archive/map/summary), управление сессией и импортом/экспортом.
- `Archive.jsx`: Список экспедиций с превью и управлением данными.
- `MapView.jsx`: Карта с трекингом, Polyline и кастомными фото-маркерами (Spiderfy).
- `SummaryView.jsx`: Аналитика прогулки (время, дистанция, средняя скорость).
- `utils.js`: Математика (Формула Гаверсинусов, фильтрация аномалий скорости).
- `FindingsLog.jsx`, `FindingModal.jsx`, `StartExpeditionModal.jsx`: Интерфейсы сбора данных.

## ✅ Реализованный функционал

- [x] **GPS-трекинг**: Запись координат в БД каждые 5 сек.
- [x] **Система находок**: Привязка фото (Base64) и заметок к ID экспедиции.
- [x] **Память сессии**: Восстановление незавершенной экспедиции.
- [x] **Управление данными**: Удаление находок/экспедиций, Hard Reset.
- [x] **Summary View**: Расчет времени, проверка цели, лента находок.
- [x] **Аналитика пути**: Расчет общей дистанции (км) и средней скорости (км/ч) с фильтрацией аномалий.
- [x] **Визуализация**: Кастомные круглые маркеры с фото, золотистое выделение целей, Spiderfy-эффект при наслоении.
- [x] **Надежность**: Экспорт и импорт всей БД в JSON файл.
- [x] **Деплой**: Публикация на GitHub Pages, поддержка PWA (manifest, standalone mode).
- [x] **Оптимизация скролла**: Исправление проблем `100vh` и `overflow` для мобильных устройств.

## 🛠 Правила разработки и именования

- **Читаемость**: Приоритет понятности над краткостью.
- **Запрет сокращений**: `f` $\rightarrow$ `finding`, `exp` $\rightarrow$ `expedition` и т.д.
- **Рефакторинг**: Постепенный вынос inline-стилей в `App.css`.

## 🚀 Ближайший план разработки

### ⚠️ Технические приоритеты (Stability & Performance)

- **[ ] Оптимизация изображений**: Внедрение сжатия фото перед сохранением в БД (избежание раздувания IndexedDB).
- **[ ] Сглаживание маршрута**: Борьба с «дрифтом» GPS (фильтрация точек для более плавных линий на карте).
- **[ ] Энергоэффективность**: Оптимизация частоты запросов к GPS в зависимости от движения.

### 🎨 Визуализация и UX (Polishing)

- **[ ] Дизайн-система**: Переход от la-hoc стилей к единому строгому минималистичному стилю.
- **[ ] Тактильный отклик**: Добавление анимаций нажатия кнопок и плавного появления элементов.
- **[ ] Полный рефакторинг**: Окончательный перенос всех inline-стилей в CSS.

### 🌟 Будущие идеи (Feature Request)

- **[ ] Авто-распознавание**: Интеграция с API для автоматического определения объекта на фото (аналог Google Lens).
- **[ ] Умный поиск**: Поиск по архиву через теги или ключевые слова в заметках.
- **[ ] Навигация к цели**: Возможность ставить точки интереса на карте до начала прогулки.
