Правила работы над проектом **«Дневник исследователя»** (`researcher-diary`).
Документ читается агентом в начале каждой сессии и обновляется в конце.

- **Агент:** Библио. **Человек:** Роберт.
- **Продуктовый контекст и архитектура:** `PROJECT_CONTEXT.md`.
- **Этот файл:** процесс, договорённости, известные проблемы, журнал решений.

## 1. Как ведётся работа

1. **Старт сессии:** прочитать `AGENT-RULES.md` и `PROJECT_CONTEXT.md`, затем `git log -5` и `git status`, чтобы понять, где остановились.
2. **Планирование:** перед правками — короткий план (что меняю, зачем, чем проверю). Не начинать с рефакторинга, если задача — баг.
3. **Конец сессии:** обновить в этом файле раздел «Текущее состояние» и «Дальше»; при необходимости — чек-лист в `PROJECT_CONTEXT.md`.
4. **Проверка перед словом «готово»:** `npm run lint` + `npm run build` зелёные, плюс ручной прогон сценария в браузере (старт → находка → стоп → архив → отчёт). Фикс без воспроизведения бага — не фикс.
5. **Один коммит — одна мысль.** Сообщения на английском, префиксы как в истории: `feat:`, `fix:`, `add:`, `remove:`, `refactor:`.
6. Коммиты и `git push` делает Роберт, если не договорились иначе. Агент не пушит в `main` без явной просьбы.
7. **Никаких решений «за спиной».** Всё, что меняет внешнего провайдера, зависимость, формат данных или заметно меняет поведение UI (тайлы, шрифты, библиотеки, API) — сначала короткое предложение с фактами и вариантами, потом ожидание ответа. Урок: 14.11.2026 агент начал перевод тайлов на CARTO, не предупредив Роберта (D-23).
8. **Бэклог — `BACKLOG.md`.** Единый список работ и идей; при закрытии пункта — переносить в «Сделано» и фиксировать решение в журнале.
9. **Паузы между цепочками команд.** Агент может выполнять команды сам, но между цепочками показывает промежуточный результат и ждёт реакции, если следующий шаг меняет состояние (сборка, деплой, миграции, правки провайдеров). Источник — заметка Роберта в разделе 0.

## 2. Язык и имена

- **UI, документация, комментарии-объяснения** — русский.
- **Код** (переменные, функции, файлы) — английский, без сокращений: `finding`, не `f`; `expedition`, не `exp`; `position`, не `pos`.
- Доменные термины (не переводить, не переименовывать):
  - `expedition` — прогулка/экспедиция (запись с `startTime`/`endTime`/`path`);
  - `finding` — находка (фото + заметка + координаты + время);
  - `goal` — цель прогулки; `isGoal` — отметка «это была моя цель»;
  - `route` / `path` — точки маршрута `[lat, lng, timestampMs]`; старые точки без времени (2 элемента) обязаны читаться по-прежнему.

## 3. Код

- React 19 + Vite, функциональные компоненты, JS (не TS).
- Состояние живёт в `App.jsx` и передаётся вниз пропсами. Не заводить стейт-менеджер без необходимости.
- **State и IndexedDB держать в синхроне вручную:** после любой мутации БД обновлять соответствующий state (см. журнал решений, D-3). Иначе получаем баг «новой прогулки нет в архиве».
- **Никаких новых inline-стилей.** Новый код — только классы в `src/App.css`. Существующие inline-стили выносим по мере касания (правило «постепенного рефакторинга»).
- **`alert()` / `window.confirm()` в новом коде запрещены.** Планируемая замена — собственные toast/диалоги (Этап 4).
- Изображения сжимаются перед записью в БД (`compressImage` в `utils.js`). Не сохранять оригиналы.
- Деструктивные операции (удаление экспедиции, hard reset, импорт) — только с подтверждением; импорт обязан быть транзакционным и не терять данные при ошибке.
- Изменения схемы Dexie — только через новую `db.version(n)` с миграцией; старые бэкапы должны оставаться читаемыми.

## 4. Данные и приватность

- Бэкенда нет и не планируется: всё в IndexedDB, ничего не уходит в сеть, кроме тайлов OSM.
- Внешние вызовы с пользовательскими данными (фото, координаты) запрещены без отдельного решения — это осознанная приватность, а не техническое ограничение.
- **Подпись карты скрыта осознанно** (`display: none !important` в `App.css`) — не «чинить» повторно. Причина: Leaflet вставляет в свою подпись-префикс флаг Украины, а Роберт не хочет политических символов в личном однопользовательском приложении. Формально это расходится с условиями использования тайлов OSM; риск осознанно принят для личного использования. Если приложение станет публичным — вернуть подпись без политической части: `<AttributionControl prefix={false} />` в `MapView.jsx` + снять `display: none`; останется «© OpenStreetMap».
- `dist/` в git не хранится, деплой — `npm run deploy` (gh-pages). `base` в `vite.config.js` должен совпадать с именем репозитория (`/researcher-diary/`).

## 6. Проверка и окружение

```bash
npm run dev              # http://localhost:5173/researcher-diary/ (без service worker)
npm run lint             # eslint, должен быть чистым
npm run check:route      # инварианты математики маршрута (без тест-фреймворка)
npm run build            # vite build в dist/
npm run preview -- --port 4173   # проверка сборки вместе с service worker
npm run deploy           # gh-pages (только по просьбе Роберта)
```

- **Service worker есть только в сборке.** В `npm run dev` он не регистрируется намеренно (`if (import.meta.env.PROD)`).
- Офлайн проверяется на preview: DevTools → Network → Offline → reload. Приложение должно открыться; тайлы карты — нет, это ожидаемо (тайлы OSM не кэшируем).

- Dev-сервер поднимается с `base = /researcher-diary/`, не забывать про префикс в URL.
- Геолокация требует HTTPS или `localhost`; для проверки карты в браузере использовать эмуляцию координат.
- Браузер Роберта (Windows) доступен агенту через Chrome DevTools MCP — можно проверять UI живьём; мобильный вид эмулировать через `emulate` (viewport + geolocation).
- **Геолокацию в фоновой вкладке браузер не отдаёт** (permission остаётся `prompt`, диалог не показывается). Для автотеста UI подменять `navigator.geolocation` через `navigate_page` → `initScript` (стаб, возвращающий сдвигающуюся точку каждые 5 сек). Проверено 06.11.2026: так прогоняется весь сценарий старт → находки → кластер → удаление → стоп → архив → отчёт.
- Тестовые данные живут в origin `localhost:5173/5199` и не пересекаются с продом на GitHub Pages; после проверки — «Полный сброс всех данных».

## 7. Известные проблемы (на 06.11.2026)

Починено в v0.1.0 (Этапы 0–1): случайное слово `Apply` в `App.css`, ломавшее `body`; новая экспедиция не появлялась в архиве; у сохранённых находок не было `id` (ломало удаление); дубли маркеров из-за неубранных кластер-групп; падение `SummaryView` без экспедиции; нетранзакционный импорт; шрифт Times у панелей на карте; длительность «1ч 60м» вместо «1ч 0м».

Починено в v0.1.0 (Этап 2, вариант A из D-11): точка маршрута хранит время → скорость считается по реальному Δt и **по времени в движении**; запись в IndexedDB троттлится (20 с + принудительно при остановке/`pagehide`); `fitBounds` на каждый тик заменён follow-режимом с тумблером; «телепорты» рисуются отдельными сегментами и не попадают в дистанцию; локальные выбросы GPS не рисуются. Инварианты закреплены в `npm run check:route`.

Починено в v0.1.0 (Этап 3, D-15): настоящий service worker — оболочка (HTML/JS/CSS/иконки) в precache, `navigateFallback` на `index.html`, офлайн-старт работает, обновления подхватываются без ручной чистки кэша. Проверено в preview: при Offline приложение открывается и пишет в IndexedDB.

Осталось (по приоритету):

1. Распознавание фото не реализовано — это ядро исходного замысла, см. D-12. Следующий крупный этап.
2. `alert`/`confirm` везде, переполнение квоты не обрабатывается, EXIF-ориентация фото не проверена (Этап 4).
3. Попап маркера собирается конкатенацией HTML без экранирования заметки (Этап 4).
4. `public/icons.svg` не используется, `src/index.css` пуст, `src/assets` пуст — удалить при удобном случае.
5. UI не обновлял `aria`-атрибуты и не имеет дизайн-системы — этап дизайна; направление задано Робертом: «строгий и спокойный» (записать как D-17 при старте этапа).

Следствие, которое надо помнить: **в свежем клоне `npm run lint` не работает**, пока конфиг не создан заново (`npm create vite@latest` генерирует такой же). Если это надоест — вернуть конфиг в git и обновить эту запись.
- **D-3 (06.11.2026).** Источник правды — IndexedDB; state в `App.jsx` синхронизируется вручную сразу после мутаций (`startExpedition`, `toggleWalking`, `saveFinding`, удаления). Причина: баг «прогулка не появилась в архиве до F5». Альтернатива (полное перечитывание БД после каждого действия) отложена как более дорогая.
- **D-4 (06.11.2026).** Если в базе есть незавершённая экспедиция, «Начать новую» продолжает её, а не создаёт дубль. Причина: восстановленная сессия оставляла «висяк» без `endTime`, и `loadData` при следующем запуске подхватывал не ту запись.
- **D-5 (06.11.2026).** `width: 100vw` у карты заменён на `100%`. Причина: горизонтальный скролл из-за ширины вьюпорта.
- **D-6 (06.11.2026).** Бэкап пишет `version` (вместо опечатки `varsion`), но при импорте читаются оба ключа. Причина: не ломать старые выгрузки; формат пока остаётся v1.
- **D-7 (06.11.2026).** Базовый `font-family` и `-webkit-font-smoothing` заданы на `html, body`. Причина: панели поверх карты рендерились Times New Roman (sans-serif был только у `.list-view-container`). Это первый шаг к дизайн-системе, а не замена ей.
- **D-8 (06.11.2026).** Длительность в отчёте считается как `hours + остаток минут` (`totalMinutes % 60`), раньше в минуты попадало общее число минут. Найдено живым тестом: отчёт за час показывал «1ч 60м».
- **D-9 (06.11.2026).** Агент вернул подпись карты, посчитав её обязательной по ToS. Роберт указал: подпись убрана осознанно, потому что Leaflet добавляет в свой префикс флаг Украины. Изменение откатано, причина зафиксирована в `App.css` и в разделе 4. Урок: если что-то выглядит как небрежность, сначала проверить историю/спросить — это может быть решением. Готовый компромисс на будущее: `<AttributionControl prefix={false} />` (подпись «© OpenStreetMap» без флага).
- **D-10 (06.11.2026).** Локальная копия `skills/` удалена из проекта: скиллы установлены глобально в `~/.agents/skills` (проверено: 7 из 9 совпадают с доступными агенту), а два дизайн-скилла есть в `~/projects/tilda/skills/`. Причина: дублирование 9 копий в каждом проекте. Индекс скиллов заменён коротким разделом 5 этого файла.
- **D-11 (06.11.2026).** Хранение маршрута — **вариант A**: время пишется третьим элементом точки (`[lat, lng, timestampMs]`), запись в IndexedDB троттлится (`ROUTE_SAVE_INTERVAL_MS = 20000`) и дублируется принудительно при остановке и `pagehide`/`visibilitychange`. Вариант B (отдельная таблица `points` + миграция Dexie v2) отложен: на прогулке в 2 часа это ~1400 точек ≈ 70 КБ против 100–300 КБ на одно фото, выигрыша нет. Переход на B должен стоить правки двух функций (`createRoutePoint`/`calculateRouteStats` + чтение пути), поэтому решение обратимое.
- **D-12 (06.11.2026).** **Облачное распознавание фото допускается.** Роберт: приватность не блокер, «в наше время всё уже уходит в Google». Это осознанное изменение прежнего принципа «данные не покидают устройство» — он остаётся правилом по умолчанию для маршрутов и находок, но не для распознавания. Что решить при реализации: провайдер (Gemini vision как основной кандидат; Hugging Face — только метки без описания; on-device — приватно, но слабо до вида), способ хранения ключа (ключ пользователя в настройках vs прокси), и UX: распознавание опционально, выключено по умолчанию, результат кладётся в `finding.recognition = { label, confidence, description, provider, model, createdAt }` (IndexedDB документная — миграция не нужна).
- **D-13 (06.11.2026).** Состояние follow-режима живёт в `App`, а не в `MapView`. Причина: правило `react-hooks/set-state-in-effect` (eslint-plugin-react-hooks 7) запрещает `setState` в эффекте, а сброс слежения при старте новой экспедиции — это событие, а не побочный эффект. Плюс состояние переживает перемонтирование карты.

Проверено: Offline → reload → оболочка открывается, IndexedDB пишет.

## 9. Дизайн-направление (черновик к этапу дизайна)

Задано Робертом: **редукционизм, строгость, серьёзность** в духе Nuevo.Tokyo (VWFNDR) и Are.na. Референс интерфейса — `temp/unnamed.jpg` (скриншот VWFNDR; папка `temp/` в git не попадает).

Что измерено на референсах:

- **VWFNDR (приложение):** фон `#000`, текст `#FFF`, значения `~#636362`, служебные подписи `~#999`, акцент `#C7E36A` (лайм), радиус 0, табличная сетка на волосяных линиях, крупные цифры низкого контраста, крупная круглая кнопка-затвор, ряд «UI COLOUR» из 7 кружков.
- **VWFNDR (сайт):** фон `#FAFAFA`, IBM Plex Mono 14/1.4, letter-spacing 0.01em, радиус 0.
- **Are.na:** `#000` / `#E5E5E5`, шкала кеглей ×1.2 (10 / 12.5 / 14.4 / 16 / 19.2 / 24), радиус 0 (контролы 3px), линии `#4F4F4F`.

Правила:

1. **Каркас — таблица, не карточки.** Секции разделены волосяными линиями, подпись секции — капитель мелким кеглем.
2. **Иерархия тоном и кеглем, а не тенями.** Значения крупные и приглушённые, подписи мелкие и светлые.
3. **Один акцент**, только для состояния и главного действия. Цвет выбирается пользователем из набора (как «UI COLOUR» в референсе) — отдельной небольшой фичей.
4. **Радиус 0.** Круг — только там, где круг означает действие (главная кнопка «зафиксировать находку»).
5. **Шрифты: Geist / Geist Mono** (SIL OFL; копии лежат в `~/repos/odin-weather-report/src/fonts`). Шрифтовой вопрос не догма — в личном проекте Роберт допускает и платные шрифты.
6. **Заметки — засечный курсив** (Georgia / Times): живой «голос» текста против техничного UI.
7. **Движение только функциональное** (opacity/позиция), без bounce; `prefers-reduced-motion` обязателен.
8. **Фото и карта — единственный источник цвета**, кроме акцента.
9. **Не копировать плотность спецификации:** капслок — только для подписей и цифр, обычный текст остаётся обычным (русский текст сплошным капслоком читается плохо).
10. **Не клонировать.** Референс задаёт правила (сетка, тон, акцент), а не внешний вид. Финальные решения — арт-дирекция Роберта (D-20).
11. **Карта:** тайлы тонируются через `--map-tint` (D-21); маршрут и точка «я здесь» — акцент.
12. **Анимации:** библиотека **Motion** (`motion/react`), скилл `~/.agents/skills/motion-design`. GSAP в этот проект не тащим. Светлую тему не делаем (D-22).
13. **Не дублировать акцент жирным.** Если состояние уже показано цветом или размером, `font-weight` не трогаем.
